# 大模型开发工程师面试题全景：从基础到 Agent 的 24 问

## 引言：2026 年，面试题成了“第二战场”

大模型开发工程师的面试，已经从“会不会调 API”进化成对整套技术栈的系统拷问。最新动态可以佐证热度：2025 年底 HN 上“100 个 LLM 面试题”合集引发热议；GitHub 上多个面试题库仓库（如 LLMInterviewQuestions，收录谷歌、英伟达、Meta 等大厂真题）保持数千星标，2026 年 9 月仍在持续更新。

本文把考点组织成五大模块 24 道高频题，每题给要点答案，并标注与系列文章的联系——**这是你面试前 24 小时的最佳复习提纲。**

## 模块一：基础理论（5 问）

**Q1：什么是 token？中文一个 token 约等于多少字？**
token 是模型处理文本的最小单位，由分词器（Tokenizer）切分，主流算法是 BPE（字节对编码）。中文场景下 1 个 token 约等于 0.5-1.5 个汉字（依分词器而定），这也是估算 API 成本的基础——1M token 输入在主流模型上约合几十万汉字。

**Q2：位置编码有哪几种？为什么 RoPE 成为主流？**
早期用正弦绝对位置编码；后来出现可学习位置编码、ALiBi 相对偏置；2023 年后 **RoPE（旋转位置编码）** 成为主流——把位置信息编码进 Query/Key 的旋转角度，天然支持长度外推和相对位置建模，LLaMA、Qwen、DeepSeek 全系标配。

**Q3：注意力机制的时间复杂度是多少？为什么是长上下文瓶颈？**
标准自注意力是 O(N²)（N 为序列长度）。上下文从 4K 涨到 128K，计算量涨 1024 倍——这正是系列「模型预测」篇讲的 KV Cache 显存黑洞与线性注意力、稀疏注意力改革的动因。

**Q4：temperature、top-p、top-k 分别控制什么？**
temperature 缩放概率分布的尖锐程度（低=确定、高=多样）；top-k 只从概率最高的 k 个 token 中采样；top-p（核采样）从累计概率达到 p 的最小集合中采样。三者组合使用：先 top-k/top-p 截断，再用 temperature 塑形。

**Q5：解码策略有哪些？**
贪心解码（每步取最高概率）、Beam Search（维护多条候选路径，适合翻译）、采样解码（引入随机性，适合生成）。推理模型（如 DeepSeek R1）还要考虑思维链长度与停止条件的设计。

## 模块二：训练与微调（5 问）

**Q6：预训练、监督微调（SFT）、指令微调的区别？**
预训练用海量无标注语料学语言能力（如系列「模型训练」篇的四段式第一步）；SFT 用高质量对话数据学“会聊天”；指令微调让模型跟随多样化指令。成本递减、数据质量要求递增。

**Q7：LoRA 的原理是什么？为什么参数高效？**
LoRA 假设微调时的权重更新是低秩的：把增量 ΔW 分解为两个小矩阵 A×B（秩 r 远小于原维度），只训练这两个小矩阵。可训练参数量从 70B 降到 0.1%-1%，单卡即可微调，且多个 LoRA 可插拔复用——这是 2026 年最主流的微调方式（QLoRA 再加 4-bit 量化）。

**Q8：RLHF 与 DPO 有什么区别？**
RLHF 先训练奖励模型模拟人类偏好，再用 PPO 等算法优化策略，流程复杂且不稳定；DPO（直接偏好优化）把偏好学习直接变成分类目标，跳过奖励模型，训练更简单稳定。2025 年后 GRPO 等轻量 RL 算法成为推理模型训练的主流（如系列「模型训练」篇所述）。

**Q9：训练中梯度消失/爆炸怎么解决？**
激活函数（ReLU/SwiGLU）、残差连接、层归一化、合理的初始化、梯度裁剪；大模型时代还要应对混合精度下溢与 loss spike（详见系列「梯度消失与爆炸」篇，Muon 等新优化器也是加分项）。

**Q10：怎么判断模型过拟合了？**
训练损失持续下降而验证集损失回升、训练与验证差距拉大——这正是系列「训练验证测试集」篇讲的信号。对策：增大数据、正则化、早停、参数高效微调。

## 模块三：推理与部署（5 问）

**Q11：KV Cache 是什么？为什么长上下文吃显存？**
自回归生成时缓存历史 Key/Value 避免重复计算，但显存与序列长度线性增长——70B 模型 1M 上下文光 KV Cache 就约 1.2TB（详见系列「模型预测」篇的表格）。

**Q12：模型量化有哪些档位？各有什么代价？**
FP16 → FP8 → INT4：显存减半再减半，但精度逐级损失。2026 年新趋势是量化感知训练（如 Kimi K3 从 SFT 起就用 MXFP4/MXFP8 训练，把量化损失焊死在训练里）。

**Q13：投机解码为什么能加速？**
小模型先草稿出 4-8 个 token，大模型一次并行验证，猜中即采纳——2-6 倍加速且输出分布不变。边界：草稿猜不准（创意任务）和高并发批处理时收益递减。

**Q14：vLLM 为什么快？**
核心是 PagedAttention（分页管理 KV Cache，消除显存碎片）+ 连续批处理（请求动态进出 batch，不用等整批结束），相同 GPU 上吞吐可提升约 24 倍。

**Q15：部署一个 70B 模型需要多少显存？**
FP16 下权重约 140GB，加激活与 KV Cache，通常需要 4-8 张 80GB 的 H100；FP8 减半到约 70GB，2-4 张即可；INT4 量化后约 35GB，单卡可部署。**先算权重，再留缓存，这是部署规划的第一课。**

## 模块四：应用开发（5 问）

**Q16：Prompt 工程的核心技巧有哪些？**
few-shot 示例、思维链（CoT）引导推理、角色设定、结构化输出约束、温度调低保稳定。2026 年 Prompt 工程正在被“系统提示 + 工具调用”的 Agent 范式吸收。

**Q17：RAG 的完整流程是什么？**
文档切分 → 向量化（Embedding）→ 存入向量库 → 检索 Top-K → 拼进 Prompt → 模型生成。RAG 的核心价值是给模型“外挂知识库”，缓解幻觉与知识截断（模型不知道训练后的事）。

**Q18：分块（Chunking）怎么选？Embedding 模型怎么选？**
分块粒度影响检索精度：小分块（200-500 token）召回精准、大分块上下文完整；常见策略有固定窗口、句级、语义分块。Embedding 模型优先选上下文相关表示的 encoder-only 模型（如 E5、BGE、GTE，详见系列「Transformer 面试题」篇）。

**Q19：Agent 是什么？核心组件有哪些？**
Agent = 大模型 + 规划 + 工具调用 + 记忆。ReAct 让模型“思考-行动-观察”循环；function calling 让模型输出结构化工具调用；MCP 协议统一工具接入标准（2026 年工具生态的事实标准）。面试加分点：讲清“工具调用失败怎么重试、多步任务怎么规划”。

**Q20：幻觉有哪几类？怎么缓解？**
事实性幻觉（编造事实）、忠实性幻觉（偏离上下文）、逻辑幻觉。缓解手段：RAG 外挂可信知识、降低 temperature、约束解码、引用溯源、评估闭环监控幻觉率（衔接系列「模型评估」篇）。

## 模块五：评估与安全（4 问）

**Q21：怎么评估一个 RAG 应用？**
三层指标：检索质量（召回率、命中率）、生成质量（忠实度、相关性）、端到端效果（任务成功率）。离线跑基准集 + 上线后 LLM-as-a-Judge 持续监控（注意 Judge 漂移，详见系列「模型评估」篇）。

**Q22：什么是基准数据污染？为什么会让分数失真？**
基准题混入训练语料，模型“背答案”而非“会做题”，分数虚高——2026 年常见基准污染率最高达 45%（详见系列「训练验证测试集」篇的攻防）。

**Q23：Prompt 注入攻击是什么？怎么防御？**
攻击者把恶意指令写进用户输入或检索到的文档，劫持模型行为（“忽略之前的指令…”）。防御：输入输出隔离、系统提示加固、工具调用白名单、敏感操作人工确认、RAG 文档源可信度分级。

**Q24：长上下文（1M token）是万能的吗？**
不是。1M 上下文能“装下”更多内容，但存在“大海捞针”效应——模型对中间位置的信息利用不充分，且 KV Cache 成本爆炸。工程上仍优先用 RAG 做精准检索，长上下文与 RAG 是互补关系。

## 结语：面试准备的“一页纸”路径

把 24 题串起来看，大模型开发工程师的面试逻辑很清晰：**理论打底（token、注意力、位置编码）→ 训练理解（微调、对齐）→ 部署落地（量化、显存、引擎）→ 应用实战（Prompt、RAG、Agent）→ 评估兜底（评测、安全）。**

准备建议：对照五大模块逐项自测，卡壳的题目回到系列文章补细节；动手做一个 RAG + Agent 的小项目，把 Q17-Q20 变成自己的实战经验——**面试官最想看到的，是你对整套技术栈的体系化理解，而不是背答案。**
