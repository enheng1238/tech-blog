# 字节、腾讯、百度、美团大模型开发工程师面试：四厂考点雷达与场景题思路

## 引言：通用题库之外，大厂考的是“适配”

上一篇《大模型开发工程师面试题全景》给了通用 24 问。但把简历投进字节、腾讯、百度、美团，你会发现面试官的问题带着明显的“厂味”——**每家都在用自己的业务场景拷问你对大模型的理解**。

中国大厂的大模型岗位有多热，数据可见一斑：GitHub 上中文大模型面试题库 wdndev/llm_interview_note 已积累近 1.5 万星标、2026 年 9 月仍在更新，AgentGuide（Agent 开发+面试题库）超 9000 星标。需要说明的是，网上流传的“XX 厂真题”多为网友回忆整理、可信度参差，本文不列具体题目，而是给**四厂考点雷达 + 高频真题类别 + 场景题答法**——这是比背题更稳的准备方式。

## 一、先搭骨架：大厂面试的知识地图

无论哪家厂，大模型开发岗的考察主线高度一致。参考 1.5 万星仓库 llm_interview_note 的章节结构，完整知识地图是十章：

**基础（语言模型、分词、词向量）→ 架构（Transformer、注意力、位置编码、MoE）→ 训练数据集 → 分布式训练 → 有监督微调 → 推理 → 强化学习 → RAG → 评估 → 应用。**

对照上一篇文章的五大模块，这十章就是它的“扩展版”。面试前按十章逐项自测，覆盖度就不会有大漏洞；其中**微调、推理、RAG、评估**四章是绝对高频区，几乎必考。

## 二、四厂画像：业务版图决定面试侧重

同一套技术栈，不同厂的问法截然不同：

| 大厂 | 核心 AI 业务 | 面试侧重 | 典型考点 |
|------|--------------|----------|----------|
| 字节跳动 | 豆包、扣子（Coze）、推荐/内容生态 | 工程 + 算法并重，代码题强度高 | 注意力实现、Agent 平台设计、高并发推理 |
| 腾讯 | 混元大模型、元宝、社交/游戏/广告 | 工程实现 + 业务场景落地 | 多轮对话、广告/游戏场景、大规模服务架构 |
| 百度 | 文心 ERNIE、千帆平台、搜索 | 算法深度 + NLP 传统功底 | Transformer 细节、预训练原理、检索与生成结合 |
| 美团 | 外卖/到店/配送 AI、商家智能体 | 业务落地导向、成本敏感 | 场景题、小模型 vs 大模型选型、Agent 工程化 |

一句话概括：**字节考“能不能造出能用的系统”，腾讯考“能不能在亿级场景跑稳”，百度考“懂不懂底层原理”，美团考“能不能用最低成本解决问题”。**

## 三、高频真题三大类

大厂真题可以归为三类，每一类都有明确的备考策略：

**第一类：八股原理题。** 考察对底层机制的掌握，高频考点包括：Transformer 各组件细节（为什么 LayerNorm 放在残差之前/之后、MHA/MQA/GQA 的区别与 KV 缓存影响）、为什么主流 LLM 都是 Decoder-only、RoPE 如何实现长度外推、MoE 的路由与负载均衡、RLHF/DPO/GRPO 的流程差异。这类题没有捷径，对照知识地图逐项吃透，能讲清“为什么”而不是“是什么”就赢了。

**第二类：手撕代码题。** 大厂普遍要求现场写核心逻辑：手写注意力（含 masked attention）、实现 top-p/temperature 采样、写一个简单的 BPE 分词、RAG 检索的向量相似度计算。准备建议：把注意力、采样、检索这三个“最小实现”练到闭眼能写——它们是面试官判断代码功底的标准样本。

**第三类：场景设计题（最拉开差距）。** 给出一个业务场景，让你设计技术方案。这类题考的是**工程权衡**：选型（微调 vs RAG vs 长上下文）、成本估算（token 费用、显存）、失败处理（检索为空、模型拒绝回答）、评估方案（离线指标 + 线上监控）。下面用四厂真实业务示范答法。

## 四、场景题示范：四厂业务 × 四套答法

**字节系：给“豆包”设计一个长文总结 + 知识库问答功能。** 答题要点：长文用 Map-Reduce 式分段总结避免超长截断；知识库走 RAG 流程（分块策略按文档类型：合同用语义分块、聊天记录用固定窗口）；检索层做多路召回（向量 + BM25）+ 重排；生成层强制引用溯源，用户可一键跳转原文——把“可验证性”作为设计的第一原则，符合字节对产品体验的极致要求。

**腾讯系：微信客服场景的智能体。** 答题要点：多轮对话状态管理（对话上下文 + 用户画像拼接）；工具调用设计（查订单、改地址等 API 白名单化，敏感操作二次确认）；权限隔离（客服只能访问所辖客户数据）；降级方案（模型超时/拒绝时回退到人工，可用意图识别兜底）。把“稳定性与安全”放在首位，因为这是亿级用户的场景。

**百度系：搜索结果的生成式回答。** 答题要点：检索增强是核心——先检索 Top-K 网页，再让模型基于检索结果生成并逐句引用；时效性问题用“检索新鲜度信号”加权；不确定时明确说“信息来自…”，不编造。百度考的是你对“检索 × 生成”这个搜索新范式的理解深度，能讲清 RAG 与搜索系统的融合就得分了。

**美团系：外卖评论分析 + 商家智能助手。** 答题要点：评论情感分析先评估——通用大模型 Few-shot 够用就别微调（省成本）；商家助手（定价、菜单优化）涉及私有数据，用 RAG 挂载商家知识库 + LoRA 微调行为风格；成本敏感场景算清每千次调用成本，给出“模型分级路由”（简单任务用小模型、复杂任务用大模型）的方案。把“ROI 与成本”讲透，最对美团面试官的胃口。

## 五、备考路线图

结合前篇 24 问与本章节，给出三个月冲刺路径：

1. **第 1 个月：知识地图扫盲**——按十章逐项过，八股题能讲清“为什么”；
2. **第 2 个月：代码 + 项目**——手写注意力/采样/检索三个最小实现；做一个 RAG + Agent 项目（参考 AgentGuide 的实战路径），能讲清楚每个设计决策的取舍；
3. **第 3 个月：场景题集训**——用四厂业务各练 3 个场景题，刻意练习“选型 → 成本 → 失败处理 → 评估”的四段式答法；
4. **贯穿全程**：关注各厂最新模型动态（豆包、混元、文心、GLM 的更新），面试官喜欢“你最近在跟进什么”的主动回答。

## 结语：大厂面试的本质

字节的工程、腾讯的场景、百度的深度、美团的成本——四厂表面考不同的东西，本质考的是同一件事：**你能不能把大模型技术，翻译成这家公司的业务价值。**

技术深度决定你过不过得了算法面，业务理解决定你过不过得了终面。用“技术 × 业务”的双视角准备，比刷一百道题都管用。
